Adversarial ML, in five minutes

Everything you need to understand the attacks AO8 runs and how to read your report.

White-box vs. black-box attacks

White-box attacks assume the attacker has full access to the model — architecture, weights, gradients. They craft perturbations using the model's own gradient, which makes them the strongest possible test of robustness. AO8 runs white-box attacks because it has your uploaded model directly: if you're not robust to white-box attacks, you're definitely not robust to weaker black-box ones.

Black-box attacks assume no internal access — the attacker can only query the model and see outputs (or not even that). They rely on transferability or querying/estimating gradients. They're a *lower bound* on how much damage a real attacker without insider access could do.

FGSM — Fast Gradient Sign Method

The simplest and fastest attack. It takes one step in the direction that increases the model's loss the most: x_adv = x + ε · sign(∇ₓ loss(x, y)). One gradient computation, done. Great as a cheap sanity check; usually the easiest attack for a model to survive.

PGD — Projected Gradient Descent

FGSM's stronger sibling. Instead of one big step, PGD takes many small gradient steps and "projects" the result back inside the allowed ε-ball after each step, so the perturbation never exceeds the budget. Considered the standard benchmark for empirical robustness — if a model survives PGD at a given ε, that's a meaningful signal.

C&W — Carlini & Wagner

An optimization-based attack that searches directly for the smallest perturbation that flips the prediction, rather than working within a fixed ε. It's slower (often minutes instead of seconds) but tends to find the true worst case, which is why AO8 flags it as the "may take a while" option.

What does epsilon (ε) mean?

Epsilon is the attack's perturbation budget — the maximum amount any input feature is allowed to change, usually measured in L∞ or L2 norm. A small ε (e.g. 0.01) means "barely visible" perturbations; a larger ε (e.g. 0.3) means the attacker is allowed to change inputs more aggressively. Robustness at low ε is a much higher bar to fail than robustness at high ε — always read accuracy drop next to the ε it was measured at, not in isolation.

How to read your AO8 report
  • Robustness score — a single 0–100 summary; above ~75 is "robust", 50–75 is "moderate risk", below 50 is "high risk".
  • Clean accuracy — how the model performs with no attack, your baseline.
  • Per-attack accuracy / accuracy drop — accuracy under that attack, and how far it fell from clean. A big drop under FGSM (the weakest attack) is a bad sign; a big drop only under C&W is more expected.
  • Flipped samples — individual inputs the attack successfully fooled, with the features it perturbed most — useful for spotting which input features your model is over-reliant on.
  • Defense comparison bars — clean vs. robust accuracy before and after each defense, so you can see the accuracy/robustness trade-off each one costs you.
